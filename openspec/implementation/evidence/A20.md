## 独立 review 的反例与修复复验

1. raw 041 选 logical 0 曾返回两 member，选 logical 1 曾空集。修复后独立 public API probe 分别只返回 0、1；committed 测试同时验证 raw/APK 的关系、classes、dexes、method inventory 和 scoped decompile。
2. interfaces_off=0x2c 曾读取 header link_size=0，误认为合法空 list。修复后独立 probe 返回 MalformedInput；committed 测试覆盖标准/041 的 header、table、map 假 list，并保持真实跨 member 列表成功。
3. 一个 class 的 32769 个不同接口 type_id alias 同字符串，旧行估算未覆盖 fold 双 Vec 容量。独立全局 allocator 测得：42,000,000-byte ledger 旧实现拒绝前新增 heap 峰值 51,021,355 bytes；修复后在行 reserve 提前拒绝，峰值 14,512,836 bytes。140,000,000-byte ledger 下完整返回 32769 边，新增 heap 峰值 51,021,379 bytes。

该 allocator 测量是一个具体输入的分配回归，不能推广为进程 RSS 硬限制或所有输入内存保证。对应结构已经纳入 committed class_relations_memory 测试；独立 reviewer 的 all-features 测试 1 passed；no-default 的关系/allocator 合计 12 + 1 passed。独立 reviewer 最终结论为 APPROVE，无剩余阻断项。
