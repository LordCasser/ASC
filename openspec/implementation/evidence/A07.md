# A07 — 集成输入与结构化分析行为（证据）

状态：已实施，集成 owner 本人实现。base `a161489`（A05），head 见本次提交。

## 交付

### 1. apk.rs 重写为结构化操作层

- `Artifact`（open 持有 owned bytes + sha256 身份 + catalog + 选中的 root entries + 重名警告）；
  `open_path`（有界读取 512MiB 上限、检查点、sha256、目录解析、根 DEX 选择）与 `open_bytes`。
- 五个操作全部返回 `Report<T>` / `Error`：`dexes`（无 DEX=空目录成功）、`classes`（全部
  class_def 保留、重名诊断、Java 名过滤）、`references`（结构化身份/目标/偏移）、
  `decompile`（ClassSelector 描述符/显式 DexId、checked 后端、041 私有 scratch、
  Completeness→Complete/IncompleteDecompilation+partial_source）、`manifest`（最后一个同名
  entry、A06 领域模型 + to_xml）。
- **契约落实**（interfaces §4）：每个 dex 操作在成功前完整 inflate+CRC+校验全部选中
  entry；entry 按中央目录序处理，最低序错误即操作错误（无 first-completed 竞态）；
  prefix 快路径删除（前缀无法证明完整校验）；解码预算跨 entry 共享。
- `--dex` 解析经 catalog：序号必须命中选中的逻辑 DEX，否则 InvalidQuery。
- 临时文本渲染标注为 interim（A08 冻结转义/排序协议）；诊断全部走 stderr。

### 2. legacy 删除（A01/A03 交接清单兑现）

- `dex::find_references/defines_class/class_names/ReferenceRow`、旧 `Dex` 结构、
  `scan_all_classes*` 系、`src/dex/prefix.rs`（前缀快速路径）、`query.rs` legacy 层
  （Query/MemberQuery/ClassQuery/format_class_name/fuzzy_class_pattern）与 anyhow 依赖全部删除。
- 后端调用收敛为 checked 路径：`parse_for_analysis` + `decompile_checked`
  （`parse_for_class`+`decompile_class` 不再被 src/ 调用）。

### 3. 集成过程中发现并修复的缺陷

1. **真实 DEX 全线 0 行 / 报错的扫描器缺陷（A03 遗留）**：`ScanDex::prototype` 把
   type_list 参数项按 u32 步长读（规范是 u16）——合成 fixture 全是零参数原型所以
   contract_references 68 项全绿，真实 APK 的 findrefs/classes/getclass 全部 MalformedInput。
   修复后 Markor 上 `method onCreate` 145 行与 A00-c 参考计数**完全一致**。
2. `backend_scratch` 扩展到普通 DEX 的完整性告警场景（G03）：checksum/signature 不一致
   → 私有副本重算字段（**先签名后 checksum**——checksum 覆盖 12.. 包含签名区，顺序反了
   会自败；这是 A02 在 make_041_container 发现的同款 bug），原始 bytes 不变、告警保留。
3. fixture 构建器勘误：`build_zip` 写真实 CRC（A02 契约校验它）；`const_string_fixture`
   补 map_list/data_off/data_size（A02 校验 tiling 不变量）；`DuplicateName.name` 字段名。
4. classes 过滤器在重写中一度丢失——clippy unused-variable 抓回，已恢复且重名计数在
   过滤**前**统计（被过滤掉的重复定义仍是重复定义）。

  原始 encoded value；注解以无损 rendered 文本携带）——A05/A12 暴露原值后填充。
