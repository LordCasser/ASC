## 交付与验证结果

### A00-a：fixture 注册表与 Rust harness（parts/A00-a.md）

- `tests/fixtures/contracts/manifest.json`：schema_version=1；集成后 61 cases（active 28 / planned 33），覆盖全部 37 个验收矩阵 ID（harness 双向断言：不得缺失也不得发明）。
- `tests/fixtures/contracts/inputs/`：g01（regex string 查询）/g02（静态初值）/g03（零 checksum）最小 fixture；Rust 构建器与 Python 基线输出逐字节一致（g02 dex sha256 `5686e4a4…f20fe`，与 Python `make_static_field_dex()` 输出 cmp 相同；harness 以常量钉死）。
- `tests/support/`：仅标准库的 DEX/APK 构建、sha256、JSON、事实比较器（multiset/有序双语义、int≠float）。
- `tests/contract_harness.rs`：8 测试全过（结构/唯一性、37 ID 覆盖、sha256/size、生成器溯源、facts 非空、比较器负向自测、字节翻转必败、opt-in 再生成）。
- 已知登记项：regex 语义按 fancy-regex is_match（非锚定 search）编码，`tok(en|x)` 命中含子串的 "tokens"；单命中场景由 `^token$` 锚点查询承担（spec scenario 文字与任一标准语义都不可同时满足，已在 manifest notes 声明）；g03 的诊断码 `DexChecksumMismatch/DexSignatureMismatch` 是提案，待 A02/A07 冻结错误码表时对齐。

### A00-b：比较器修复与自测（parts/A00-b.md）

- `bench/corpus_parity.py` 重写：行 multiset 双向比较（重载/重复行按出现次数配对）；manifest 差异计 failure 且比较 text/tail（renderer 空白归一规则明确，非空白内容不可归一掉）；豁免机制 `bench/parity_allowlist.json` 精确到 (apk sha256, query, row identity)，未命中的豁免本身是 failure；`--self-test` 17 项全过（删真实引用、改 XML text、改属性值三种篡改必败，对照对必过）。
- `bench/row_oracle.py` 重写：基于 ccc6bae 逐行核实并纠正两个旧错误断言——(1) 参考 InsnLocator **有**指令边界验证（16 字节密集桶 + INSN_VERIFY.fullmatch 回验，insn_locator.py:169-204），残留路径是桶列表只对 midx[0] 验证、链正则可穿 switch/array payload（payload 首单元 0x00=nop）；(2) member 查询按**成员名**正则匹配（string_locator.py:55 → method/field_locator 按名字符串 idx 映射），不匹配整个 `Lclass;->member`（那是 asc_handler.py:69-78 的展示格式，无 prototype）。身份含 matched text 以缓解重载合并。
- 冒烟：workload DEX 自包 APK 下 C09 锚点复现（onCreate 84 / INSTANCE 1055 / type Activity 133 行 multiset 一致）；NewPipe 全流程 10 个 sweep DIFFER 如实计败（双向比较捕获的 asc-only 行，待 row_oracle 仲裁——这是已知未分类差异，不是通过）。
