## 5. 预筛等价证据

- 行为等价：`ref03_prefilter_toggle_is_result_equivalent` 对 3 个输入 × 9 组查询（string/type/field/method、literal/regex、含😀与控制字符）断言 on/off 结果逐值相等 —— 通过。
- 实现等价论证：`Targets::might_reference(code)==false` 当且仅当 code 中不存在任何目标索引的小端操作数字节（2 字节对双端核查 + 4 字节 memmem），此时每条指令读出的操作数都不可能 `contains` ⇒ 跳过操作数匹配不改变命中集合；指令边界解码无条件执行（#8），因此**错误行为也与开关无关**（未知 opcode/截断流在 on/off 下同样失败）。
- 单元测试：`filter::tests::explicit_prefilter_switch_only_disables_acceleration`、`byte_filter_matches_the_unfiltered_scan`。

dex::scan_references(
    view: &dex::DexView<'_>,

语义要点（A07 透传给 CLI 时不得改变）：

1. 行序 = method_idx 升序；行内目标 = 表索引升序；`code_unit_offsets` = 指令起始相对 insns 数组头的 16-bit 单元偏移，构造时升序去重（`TargetMatch::new`）。
2. 错误面：查询/表/字符串声明超限 → `ResourceLimit`；字符串编码/终止符/未知 opcode/截断指令流 → `MalformedInput`（带 `method #N` / `string #N` 上下文）；regex 遇未配对 surrogate → `UnsupportedEncoding`（字面量对同一候选可判定且照常命中）。
3. **空目标集仍完整遍历**：类数据与指令边界校验是无条件义务（本包 #8 的合同依据），A07 不得把"无匹配"优化成提前成功。
4. 重载不合并：每个 (DexId, method_idx) 独立成行，即便共享 code_item。
5. `ScanOptions.control` 在 scan 入口、每方法、长循环每 ≤4096 code units 检查（`Cancelled{User/Deadline}`）。
6. manifest.json 的 4 条 A03 条目已 active（含 sha256/size/facts_path），A09 的 registry 消费无需再改。

**legacy 桥接现状**：`dex::{find_references, defines_class, class_names, ReferenceRow}`（文本行形态）与 `query.rs` 的 legacy 层（`Query/MemberQuery/ClassQuery/format_class_name/fuzzy_class_pattern`）仍被 `apk.rs` 使用；`dex::prefix` 提供 string-only 前缀快速路径。A07 切到 `scan_references` 后整体删除，不再扩展。

## 7. 已知限制

1. **预筛收益收缩**：因为边界校验无条件执行，预筛现在只省"操作数匹配"，不再省整段指令解码（旧 legacy 路径的省法与合同 §4/等价性冲突）。若 A11 基准显示这不够，需要合同层明确放宽（并接受 on/off 对畸形输入的分化）或另设快速结构校验通道。
2. **理论上的跨条目伪解码**：有界解码以"声明 unit 数"为准；若恶意输入声明远大于实际的 unit 数、payload 区内无 raw NUL、且后续（相邻条目）字节恰好构成合法 MUTF-8 并在声明处紧跟 0x00，理论上可解码出跨条目的伪值。已杜绝的是 NUL 扫描式伪匹配与越界读；该残留缺口是确定性行为（无 UB），留给 A11/A14 的 fuzz 校准，必要时再加"相邻 payload 偏移上界"（需 O(n) 偏移表，当前为避免每扫一笔 16MB 内存而未做）。
3. **legacy 路径仍是 NUL 扫描**（`Dex::string_bytes`/`prefix.rs::string_at`）：显示路径对畸形串的行为与结构化路径不同（lossy），A07 删除 legacy 后自然收敛。
4. **harness 的常量 artifact**：`memory_view`/`named_view` 用固定 ArtifactId（理由见 #6）；若未来出现需要跨输入比较"身份含 artifact"的用例，需要重新审视该 harness 决定。
5. 并行扫描拆分：结构化扫描当前串行遍历类数据（与 legacy 的 rayon 拆分不同）；大 DEX 的并行化属 A11 性能范畴，不影响结果（命中按 BTreeMap 归并）。
