## 7. 参考实现已知缺陷与比较注意（不判断对错，只固定"它当时输出什么"）

- **身份错配类（审计 G02/D02/D03 家族）**：findrefs 行的 `class->method` 标签常张冠李戴，例如 NewPipe string youtube 输出里出现 `Lorg/jsoup/Jsoup;->getVisionOsPlayerResponse`、`Landroidx/work/OperationKt;->resolveChannelId`——方法名与所属类明显不匹配。expected 文件按原样保存；A09 比较器不得把该标签当语义真值，差异需按 QUAL-01 的 expected-difference 流程登记。
- **matched 不转义**：string 查询的 `matched=(…)` 原样嵌入字符串内容，字符串自身可含换行/制表符（如 Markor 内嵌 HTML 模板、AntennaPod deeplink URL），因此 string 查询的"行数"是物理行数而非记录数，逐记录比较需按 `dex | class->method | matched=` 前缀归位后再取 matched 原文。
- **块间顺序**：findrefs 由进程池 FIRST_COMPLETED 完成序拼接各 DEX 块，理论依赖调度；本次受控复跑 2 次字节一致（与存档排序后亦一致）。比较器应按行集合或按 dex 前缀分块比较，不依赖块间顺序。
- **classes/manifest/getclass** 均为确定性输出（sorted / pretty XML / 单类反编译）。
- workload 的行数与 `reference-baseline.json` 的 count 口径不同（后者数 method idx，前者数聚合后的输出记录），不构成矛盾。
