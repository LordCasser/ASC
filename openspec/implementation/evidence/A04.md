## 3. checked API 冻结（A05/A07 直接消费）

模块 `droidsaw_dex::analysis`（lib.rs 已 re-export 主要类型；模块路径为规范路径）：

```rust
pub fn parse_for_analysis<'a>(view: &'a [u8], options: &ParseOptions,
    budget: &Budget, control: &Control) -> Result<ParsedDex<'a>, BackendError>
pub fn decompile_checked(parsed: &ParsedDex, selected_class_def_idx: usize,
    emit: &EmitOptions, budget: &Budget, control: &Control)
    -> Result<BackendReport, BackendError>
```

语义要点（A05 必读）：

1. **ParseOptions { scope: ParseScope }**，默认 `ParseScope::Full`。`ScopedToDescriptor { descriptor }` 沿用现有按 descriptor 的 scoped parse（匹配不到自动回退 full 并由 `ParsedDex::scoped_fell_back_to_full()` + `ScopedFallbackToFull` 诊断报告）。Full 与 Scoped 都走"decompile 解析形状"（`parse_view(view, false, …)`）：所有请求的 class bodies/注解/debug；emit-only 表（whole-input SHA-1、method handles、call-sites、section-walk 错误通道）两种 scope 一致跳过——这是 DX-P01 已登记行为，不破坏 full/scoped 等价。A05 若需要 call-site/handle（invoke-polymorphic/custom），这是已知缺口，须先扩 `parse_view` 的 emit_support 语义并在账本登记。
2. **ParsedDex<'a>** 借用调用方 view（不复制输入）；`dex()`/`scope()`/`scoped_fell_back_to_full()`/`parse_error_count()` 只读访问。decompile 只接受该类型 → 不会重读输入。
3. **EmitOptions { trace, line_comments, panic_on_err }** 全默认 false；ASC 必须传 false/按需——三者分别对应原 `DROIDSAW_DECOMPILE_TRACE`、`DROIDSAW_DEX_EMIT_LINE_COMMENTS`、`DROIDSAW_PANIC_ON_DECOMPILE_ERR`。
4. **Budget { deadline: Option<Instant>, max_input_bytes: Option<u64> }** 最小冻结形状：max_input_bytes 在 parse 入口一次性计量；deadline 在 §5 检查点查询。A11 对接时可扩字段，不得改语义。
5. **Control { cancelled: Arc<AtomicBool> }**：`new()`/`cancel()`/`is_cancelled()`；Clone 共享。core 的 CancelToken 映射为 clone + cancel 闭包即可。
6. **selected_class_def_idx** 直接索引 `parsed.dex().class_defs`（重复 descriptor 不会被重选）；越界 → `BackendError::InvalidClassDefIndex`。
7. **BackendError**：`Dex(DexError)`（typed，可 match）/`Cancelled`/`DeadlineExceeded`/`InputBudget{bytes,cap}`/`InvalidClassDefIndex{index,class_defs}`。建议 core 映射：Dex→MalformedInput 族；Cancelled/DeadlineExceeded→Cancelled(cause=User/Deadline)；InputBudget→ResourceLimit；InvalidClassDefIndex→InvalidQuery。
8. **BackendReport { source, completeness, diagnostics, method_outcomes, metadata }**：
   - `Completeness::Complete | Incomplete { reasons }`；reasons 类型见下。非空 reasons ⇒ 不得当完整成功（DECL-04）。
   - `MethodStatus`：`Emitted` / `DeclarationOnly{kind: Abstract|Native|NoCode}` / `Suppressed{reason: EnumSyntheticMethod|KotlinFacadeSynthetic}` / `Unsupported{regions, detail}`（方法体含非 sentinel 的未识别字节码签名区域）/ `Failed{detail}` / `Indeterminate{detail}`（已定义；当前产生源为类级 detector，A05 接方法级）/ `Cancelled`。后三族 + Cancelled 不能组成 Complete。
   - `MethodOutcome { method_idx(身份), name(尽力，"?"时伴随 UnresolvedName 诊断), is_direct, status }`，direct 在前 virtual 在后、class_data 序。
   - `BackendDiagnostic { code: DiagnosticCode(机器身份), message(非机器), method_idx?, field_idx? }`。code 集合：StaticInitializerDropped/StaticInitializerDefaulted/MethodFailed/MethodUnsupported/DetectorIndeterminate/UnresolvedName/UnresolvedType/ScopedFallbackToFull/R8OriginCommentsDropped/ParseErrorsPresent。
   - `IncompleteReason`：MethodFailed/MethodUnsupported/MethodIndeterminate/MethodCancelled/StaticInitializerDropped{field_idx}/DetectorIndeterminate{detectors}/ParseErrors{count}。**ParseErrors 只计"子段丢弃型"parse_errors**（AnnotationDirectory/AnnotationSet/AnnotationSetRefList/AnnotationItem/EncodedArray/ClassData/CodeItem/DebugInfo/Interfaces）；池序/重名 class_def/拓扑/保留位等结构异常只出 `ParseErrorsPresent` 诊断不计入 completeness——否则 G02 这类合法 fixture 会被无关 StringIds 乱序（Python 基线 fixture 即如此）永远判 Incomplete，堵死 A05 的 DECL-01 通过路径。A05/A07 如需按选中类过滤 parse_errors 再收紧。
   - `BackendMetadata { class_def_idx, descriptor, access_flags, super_descriptor, interfaces, source_file, static_fields, instance_field_count, method_count }`；`StaticFieldReport { field_idx, name, type_descriptor, access_flags, encoded_value_java, initializer_emitted, drop_reason }`，`InitializerDropReason`：`NonFinalStatic`（G02 缺陷，计 Incomplete）/`AssignedInClinit`（有意的 javac 约束，不计 Incomplete）/`R8InlinedAssignment`（有意）/`UnrenderableValue`（值渲染失败被零值掩盖，计 Incomplete）。A05 扩展 metadata（注解/throws/inner/enclosing/debug）在 DX-P05 下加字段，不改已有字段语义。

## 6. scoped/parallel 等价与 G02 结构化呈现（BACK-03 初步）

- `scoped_parse_equivalence`：full vs ScopedToDescriptor 在 G02 上 source/metadata/method_outcomes/completeness 全等；scoped 附 `R8OriginCommentsDropped` 诊断、full 无；未命中 descriptor 回退 full 且附 `ScopedFallbackToFull`、source 与 full 全等。已知不等价（R8Origin 注释）如实登记并默认 Full——符合"不等价时关闭优化"的降级策略（优化保留为 opt-in，ASC 默认不开）。
- 并行 string pool：错误/资源控制不变（count 预先 bound_count、有序 collect 保首错），DX-P02 登记其检查点结论。
- **G02 当前缺陷的结构化呈现**（`g02_static_initializer_drop_is_reported`）：`Lexample/Statics;` 的 FIRST/SECOND `encoded_value_java` 分别为 Some("11")/Some("22")、`initializer_emitted=false`、`drop_reason=NonFinalStatic`；completeness 恰为两条 `StaticInitializerDropped`（无其他噪音 reason——这也是给 A05 的靶子：修好 DX-P04 后 G02 应变 Complete）；源码确认仍不含 `= 11`（A04 只报告不修）。方法面：getSecond Emitted。
- DECL-04 rails：`declaration_only_outcome`（字节级 uleb 重写造出 abstract+code_off=0 的方法 → `DeclarationOnly{Abstract}`，且不额外引入 Incomplete）；`failed_method_outcome`（insns_size 越界使 parse_code_item 失败 → `Failed{detail}` + MethodFailed 诊断 + Incomplete reason）。注意：**改单 opcode 字节不足以制造 Failed**——tolerant decode 把未映射 opcode 记为 invariant violation 后跳过继续发射（这本身佐证了"不能靠源码猜测状态"的必要性）。`Unsupported`/`Indeterminate` 状态已实现（分别由 stmt 树 walk 与 detector 集产生），带真实 fixture 的正向用例随 A05 的 DECL-02/03 矩阵补齐。
- `legacy_bridge_matches_checked`：`DexFile::parse_for_class` + `classes::decompile_class`（干净 env）与 checked 默认 options 产出逐字节相同 source —— A07 换线前的桥接锚点。
