## 3. 14 个失败的逐一根因与修复

根因分类：**[实现]**=实现缺失/顺序错，**[语义]**=错误分类或语义判定错，**[夹具]**=fixture/测试常量错（断言零改动，修复依据见 §4）。

1. **container::tests::version_matrix_accepts_known_and_rejects_others** —— [夹具]+[语义]。三处叠加：① `valid_skeleton` 把 map_list 第一项写在 `map_off` 本身，覆写了 u32 `map_size` 字段 → 校验器读到 0 → "missing the string_ids item"；② skeleton 完整性字段全零但断言"一致的字段不得告警" → 按格式 finalize（签名 sha1[32..end) 先写，adler[12..end) 后写）；③ `dey036\0` 是 7 字节字面量却按 `data[..8]` 拼入 → `copy_from_slice` panic → 按字面量长度拼接；④ 实现侧 `dey` 以 4 字节词比较永不命中（`dey0`）→ 3 字节前缀。
2. **container::tests::structural_contradictions_are_located_errors** —— [夹具]。同 1①；另 `SKELETON_MAP_ITEM_KIND=4` 在修正布局下指向第 1 项的 kind，而注释钉死"map 的第二项伪装成未登记 kind" → 常量按既有约定（map_off+size 4+一个 item 12+字段内偏移）改为 16（`SKELETON_MAP_STRING_IDS_OFFSET=4+12+8` 本就按此约定写，两常量原本互相矛盾）。
3. **container::tests::integrity_mismatch_is_a_warning_not_an_error** —— [夹具]。同 1①/②：校验从未走到完整性阶段。修复后 patch 0x08/签名得到恰好 2 条 Warning、字节不变。
4. **container::tests::backend_scratch_rewrites_the_041_header_without_touching_the_original** —— [夹具]。`valid_skeleton(base=180)` 在 `total` 长缓冲上按 `base+X` 绝对位置写入 → 越界 panic（184 > 180）。重写为：缓冲=成员自身 span（相对位置），指针字段携带绝对地址（`base+X`）——与该构建器 map 项/string_ids 值原本就写绝对地址的写法一致；`extend_from_slice` 拼出的两成员容器随之自洽。
5. **in01_dexless_archive_reports_notfound_for_dex_backed_operations** —— [语义]。`used_fallback` 在 classes*.dex 层为空时无条件置 true，即使 fallback 层也为空；测试钉死"无 DEX 时 used_fallback=false"。改为 fallback 层实际产出选择才算 used。
6. **in02_bad_eocd_and_ranges_are_located_structural_errors** —— [实现]。子例把 cd_offset 改 0（区间 shortfall），旧实现只查 `cd_end > eocd`，随后从 offset 0 起行走并报局部头签名错误。补"目录区间与 EOCD 齐平"不变量（APK 工具链产出必然齐平；已用 python3 验证全部已提交 fixture 含 g03 齐平）。
7. **in02_actual_size_and_trailing_stream_are_rejected** —— [实现/顺序]。`read_entry` 在解码前比较本地头与中央目录的 CRC/sizes；子例只改中央目录 declared size，预检抢先报"local header CRC/sizes disagree"。按 §4 合同（解码前只钉 name/method/关键 flags 一致）把该检查移到流校验（精确尺寸/尾流/CRC-32 对中央目录）之后，"decoded"/"exceed the declared"/"stored sizes disagree" 如期先触发。
8. **in02_selected_entry_crc_mismatch_fails_with_entry_and_offset** —— [实现/顺序]。同 7：CD CRC 被改坏（0xDEADBEEF）而本地头真实值触发预检。移动后 CRC-32 mismatch（含 entry 名与 local/data 偏移）如期报出。
9. **in02_descriptor_values_must_match_the_actual_stream** —— [夹具]。截断 descriptor 子例 `apk.truncate(len-4)` 砍的是 EOCD 尾 4 字节（`eocd+22 > len`，任何解析器都不可能成功），且 descriptor 本体在档中段完好、根本不会报错。构造改为删 descriptor 尾 4 字节并令 CD/EOCD 前移（cd_offset-=4）；断言 `contains("descriptor")` 不动。
10. **in03_versioned_fixtures_carry_real_structural_differences** —— [夹具]。`support::dex::make_dex`（冻结、只读）在 offset 128 处天然含字节对 `FE 00`（string_ids[4]=254=0xFE，即 "second" 串偏移），与 const-method-handle 指令字节（opcode 0xfe + AA）不可区分；而该 APK 的 classes.dex 恰是 make_dex。换成真 035 版本构建器产物（类名按断言保持 `Lexample/Test;`），404 字节、无 FE 00。
11. **in03_container_041_single_member_keeps_name_and_multi_member_shares_address_space** —— [夹具]。`make_041_container` 先算 adler 再写签名，而 adler 覆盖区间 [base+12..end) 包含签名字段 → 每个成员 checksum 必错 → 诊断非空。finalize 顺序改为签名先行、checksum 收尾（与 `make_version_dex`/DexBuilder 一致）。
12. **in03_broken_containers_are_structural_errors_without_fallback** —— [实现]。overshoot 变体（成员 0 file_size=整容器）依然精确铺满容器，链行走成功。补孤儿头不变量校验（见 §1）：被吞成员头的自指 header_offset 与链矛盾 → 定位报 MalformedInput；三个变体（undersize/overshoot/self-offset）各自独立失败。
13. **in03_compactdex_odex_and_unknown_versions_are_unsupported** —— [语义]。① `dey` 4 字节词永不匹配 → 报成 MalformedInput("bad magic")，改为 3 字节前缀；② 测试对同一 fixture 的每个 entry 依次断言 CompactDex 与 ODEX 两个 needle，故 cdex/dey 两条拒绝共用一族消息（"alternative DEX image (CompactDex `cdex` / ODEX `dey`) is outside the supported matrix"）。未知版本 036/099 走 magic→版本矩阵次序，消息含 "outside the supported matrix"。
14. **manifest_a02_cases_agree_with_the_committed_facts** —— [夹具/登记]。manifest 无任何 active A02 条目（11 条 planned、input=null），测试要求 ≥13。补齐/新增共 13 条 active（含 input sha256/size、6 个 pass 用例的 dex_catalog facts、2 个新 case），`checked=13`。

另：编译警告 `function sha1 is never used` 属于 A02 层尚未被二进制调用图接线的过渡态，按仓库既有先例（query.rs）以注释性 allow 压制，A07 接线时删除。

## 4. 测试常量/夹具证据（python3 独立验证）

1. **make_dex 含 FE 00**：从已提交 `in01-root-dex-priority-and-dupes.apk` 提取 stored `classes.dex`（432 B），`b'\xfe\x00' in dex == True`，首现 offset 128 = string_ids[4] = 254 = 0xFE（"second" 的 string_data 偏移，LE 存储 FE 00 00 00）。因此 in03 版本矩阵的 035 成员必须换图，而非改测试。
2. **版本构建器 python 复刻逐字节一致**：按 `make_version_dex` 语义复刻的 python 构建器与已提交 fixture 中 stored 的 classes3.dex（v038, 440 B）、classes5.dex（v040, 444 B）完全相等；按其构建 `b"035\0"`/`"Lexample/Test;"` 产物 404 B、不含 FE 00、含 `Lexample/Test;`（满足冻结的 class_names 断言与 map_size==10、version=="035"、ids==(0,0) 断言）。
3. **EOCD 截断不可解析**：`apk.truncate(len-4)` 后 `eocd+22 > data.len()`（EOCD 固定 22 字节、cd_offset 高 2 字节已丢失），证明"截 descriptor"子例原构造在数学上不可满足，只能改夹具构造；断言未动。
4. **齐平不变量安全性**：python 校验已提交 `g03-zero-checksum.apk`（cd [473..530]=EOCD@530）与全部相关 fixture 均 `cd_offset+cd_size == eocd`；本测试目标的全部输入都出自 `build_contract_zip`/A00 writer，天然齐平。
5. **SKELETON 常量约定**：修正布局（items 从 map_off+4 起）下，`HEADER+8+24 = 144` = 第 2 项 offset 字段（`SKELETON_MAP_STRING_IDS_OFFSET` 原值已按此约定正确）；`HEADER+8+16 = 136` = 第 2 项 kind 字段（原常量 4 指向第 1 项，与注释"the map's second item masquerades as an unchecked kind"矛盾）→ 改 16。6 处 `structural_contradictions` 的 needle（file_size/header_size/endian/string_ids/map_list item…/missing the string_ids item）逐一推演满足。
6. **manifest facts 数值**：全部 `dex_catalog` 行与诊断由 regen 辅助测试在实际管线上打印后原样录入（非手算）；`manifest.json` 的 sha256/size 同源。

## 5. 给 A03/A07 的接口说明（签名与语义）

均位于 `src/zip.rs` / `src/dex/container.rs` / `src/bytes.rs`，`pub(crate)`，测试目标经 `#[path]` 直编。

- **`zip::parse_catalog(data: &[u8], limits: &InputLimits) -> Result<ArchiveCatalog, Error>`**：archive 级一次性校验（单卷、非 ZIP64 [0xFFFF 计数/0xFFFFFFFF size/offset/local-offset/version≥45]、非加密、entry 数限额、CD 区间齐平 EOCD、逐记录签名/名字越界、记录数一致）。`ArchiveCatalog{entries: Vec<ArchiveEntry>, duplicates: Vec<DuplicateName>}`；`ArchiveEntry{ordinal(CD 序，从 0), raw_name: Vec<u8>(原始字节，唯一键), method, flags, version_needed, crc32, compressed_size, uncompressed_size, local_header_offset}`，`display()` 为 UTF-8 优先/逐字节转义。
- **`zip::select_root_dexes(&ArchiveCatalog) -> RootSelection`**：根 `classes*.dex` 优先、否则任意根 `*.dex`（fallback；`used_fallback` 仅在 fallback 实际产出选择时 true）；同名去重保留第一条，全部原名+全部原 ordinal 经 `duplicates`/`selection.duplicates` 呈报（选择策略归 A07；"重名取第一 + DuplicateEntryName warning" 的告警发射点在 A07 汇总层）。`require_selected()` 空选时 `ErrorKind::NotFound`（"the archive contains no root DEX entry to analyse"）——A07 把 classes/references/getclass 映射到它，dexes 走空 catalog 成功。
- **`zip::read_entry(data, entry: &ArchiveEntry, limits, decoded_bytes: &mut u64, control: &ControlProbe) -> Result<Vec<u8>, Error>`**：检查序 = control.check → 本地头存在/签名 → 本地名/方法/关键 flags(0x20A9) 一致 → 加密/ZIP64 → 方法分派（stored 精确尺寸；deflate 严格流：完整消费、不超 declared、无尾流）→ 累计解码限额 → CRC-32 对中央目录（带 local/data 偏移定位）→（无 descriptor 时）本地 CRC/sizes 对目录 → descriptor（有/无签名两种拼写）核对实际流。错误族：MalformedInput/UnsupportedFormat/ResourceLimit/Cancelled{User,Deadline}。64 KiB 检查点节奏已内建。
- **`container::validate_dex_entry(artifact: ArtifactId, entry_ordinal: u32, raw_entry_name: &[u8], data: &[u8], control) -> Result<(DexEntryViews, Vec<Diagnostic>), Error>`**：magic 判序 = `dex\n`+版本矩阵（035/037/038/039/040/041；036/099 等 → UnsupportedFormat，消息含 "outside the supported matrix"）→ `cdex`/`dey` 前缀 → UnsupportedFormat（家族消息含 CompactDex 与 ODEX）→ 其他 magic MalformedInput。结构校验（header_size/endian/六表越界与头部重叠/map_list 双向核对/data 铺满）全部带定位 MalformedInput；041 走成员链（tiling + 容器尺寸/自指偏移 + 孤儿头检测），失败无降级。完整性（adler/SHA-1）不匹配只产出 `DiagnosticCode::{DexChecksumMismatch,DexSignatureMismatch}`（Severity::Warning、Stage::Dex、`.with_dex(id)`），顺序 checksum→signature；**绝不改输入字节**。
- **`DexEntryViews{views, raw_entry_name, entry_display_name}`**：`views` 与成员链同序；`dex_entry(logical)` 产出公共 `DexEntry`。`ValidatedDexView`：`bytes()` 返回**整个物理条目**（041 成员共享同一缓冲，仅 header_offset 不同；`std::ptr::eq` 可验证）、`header_offset()`、`id()`（DexId = artifact+entry_ordinal+logical_ordinal，链序稳定）、`version().as_str()`（"035"…"041"）、`logical_name()`（单成员=条目名；多成员=`<entry>!classesN.dex`，N 从 1 起）、`header()`。
- **`container::backend_scratch(&ValidatedDexView) -> Option<BackendScratch>`**：非 041 → None（后端直接用原字节）；041 → `BackendScratch{bytes(整容器私有副本，成员头覆盖至 0，header_size→0x70、file_size→整容器、adler 重算), source_header_offset(映射回容器的原头偏移), rewrites(静态说明)}`。操作期私有、不落 artifact、不改原字节、不改诊断。
- **`zip::display_name(&[u8]) -> String`**、**`zip::InputLimits{max_entry_bytes:256 MiB, max_total_decoded_bytes:1 GiB, max_archive_entries:100_000}`（DEFAULT 常量）**、**`bytes::ControlProbe{cancelled: &AtomicBool, deadline: Option<Instant>}`（`never()`/`check()`，A11 换真 OperationControl）**、**`bytes::Checkpoints`（64 KiB 节奏）**。

## 6. 已知限制

- **齐平 EOCD 不变量**：CD 结束与 EOCD 之间有杂散字节的档会被拒（APK 工具链不产出，ZIP 规范允许）；A11 corpus 校准如遇反例需放宽为"区间不越过 EOCD"。
- **孤儿头扫描**：O(容器) 逐位置 windows 匹配；成员**数据**若恰好内嵌"自洽 041 头"（magic+自指 header_offset+正确 container_size）会被误判为 swallowed——对抗性构造，真实 APK 未见。
- **替代格式消息**：cdex/dey 共用一族消息是契约 needle 决定的（每个 entry 同时断言两个格式名），不能只点名实际命中的那个。
- **过渡 allow**：`src/zip.rs`/`src/dex/container.rs` 的 A02 层 `#![allow(dead_code)]` 与 `src/bytes.rs` 的 sha1 allow，均在 A07 接线、删 legacy bridge 时一并删除。
- **4 GiB 上下的 u32 字段**：ZIP/DEX 尺寸字段按 u32 语义校验，ZIP64 形态整体 UnsupportedFormat，未做 u32 溢出回绕的容错。
- 会话期间同一工作区有并行 agent（A03/A05/A06）持续写入；本包门禁读数以 §2 的最终一轮为准。
