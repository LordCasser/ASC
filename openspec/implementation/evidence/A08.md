## CLI-02 对照（输出协议）

- text findrefs：`<entry>:<logical> | <dex-display-name> | <method_idx> | <owner>-><name>(<params>)<ret> | <targets-json>`，前四列文本转义、末列纯 JSON。g01 冻结字节（`contract_cli`）：

  ```text
  0:0 | classes.dex | 0 | Lexample/Regex;->mark()V | [{"id":{"artifact_id":"eecc…","entry_ordinal":0,"logical_ordinal":0,"index":4},"kind":"string","value":{"text":"token","utf16":[116,111,107,101,110]},"code_unit_offsets":[0]},…]
  ```

- text classes：七列 `dex-key | dex-name | class_def_idx | descriptor | java-name | package | simple-name`，冻结字节。
- text 空集 = 0 字节；json 空集 = 完整 envelope（`"data":[],"diagnostics":[]}` + LF），字节断言。
- json envelope 固定键序 `schema_version,operation,artifact_id,data,diagnostics`；stats/timing 不入 payload（`--debug` 字节不变测试）。
- getclass json data = `{class,source,metadata}`，metadata 为 typed 投影（`schemas/goldens/source-metadata.json` 冻结：flags、super/interfaces、generic signature、enclosing 三元组、inner classes、注解含 encoded array/long、字段初值 int/double bits、方法 throws/注解/参数 signature/debug locals+lines；当前后端未暴露的子结构按 schema 以 null/空数组输出）。
- manifest json data = `{xml,document}`；xml 完整生成（失败即整命令失败）；document 为有序领域文档 DTO（`schemas/goldens/manifest-document.json` 冻结）。text 与 json 的 `xml` 字节一致。
- 转义规则单测：`src/render.rs::tests`（含代理对/非配对代理/控制字符/`|`、`\`）。

## CLI-03 对照（输出提交与失败）

- 一次序列化、同 bytes 给 `-o` 与 stdout：`output_file_receives_exactly_the_stdout_bytes`（text+json，`cmp` 语义断言）。
- 有界序列化：dto `Writer` budget 增长前拒绝（`writer_budget_freezes_output_and_reports_resource_limit` + `bounded_copy_refuses_to_exceed_the_budget`）；CLI 侧 `--limit result-bytes=64` → `ResourceLimit` exit 1（黑盒）。每 item/每 64 KiB 检查 control。
- `-o` 原子替换：同目录隐藏临时文件 + flush + sync_all + rename；已有普通文件被替换（测试以旧内容起步后断言被覆盖）；无残留临时文件（`atomic_replacement_leaves_no_temporary_files_behind`）。
- 拒绝面：目录 / symlink / 与输入同文件 / 输入 hardlink（dev+ino）全部 `OutputRefused` exit 1 且输入原样（`output_refuses_directory_symlink_input_alias_and_hardlink`）。
- 提交点语义：文件写失败不发送 stdout payload（`failed_file_write_sends_no_stdout_payload`）；stdout 失败不回滚已写文件（commit 先于 stdout 的顺序保证）。
- SIGPIPE：Unix 恢复 `SIG_DFL`（A07 起）；`| head -c 1` 黑盒断言无 panic 输出（`closed_pipe_terminates_quietly_without_panic_output`）。BrokenPipe 兜底为静默 exit 0（Windows 语义）。

## 已知限制与待办

1. **Ctrl-C 不可移植**：CLI 不安装信号处理器（core 亦不装）；用户取消经 A11 的 cancel flag 兑现。deadline 取消用 `--timeout-ms 1` + 小 fixture 在快机上可能先完成，故 `deadline_cancellation_exits_130_and_names_the_cause` 标记 `#[ignore]`，A09/A14 以大 corpus 转正式。
2. **单 item 内部无检查点**：json 单个 reference/单个 metadata 对象的序列化内部（dto writer 无 control 句柄）在 item 边界检查；单 item 理论上可达 MB 级（1M offsets），期间 deadline 响应受写入速度限制。文本路径按行/64KiB 检查。
3. **`-o` 对不存在父目录、跨介质**等报 `OutputIo` exit 1；Windows 的 rename 原子性（先 remove 后 rename 的窗口）与真机行为留给 DIST-03；真机 BrokenPipe 行为同留 DIST-03。
4. **manifest plain-XML 原始字节例外**（保留原换行/BOM）未消费：`Manifest::raw_bytes` 当前恒为 None（A06 保留字段），text 输出一律走 to_xml 规范渲染。
5. **SourceMetadata 部分子结构暂为 null/空**（throws/parameter signature/debug/注解 typed items）：随 A05/A12 暴露原始 encoded value 后填充；DTO 形状已冻结，填充为纯数据变化。
6. **`field INSTANCE` 差 1** 等扫描计数问题沿 A07 记录移交 A09，与本包无关。
