## 3. src/manifest.rs 修复清单（重写稿 → facts 一致）

1. **读方法签名**：`XmlAttribute::namespace/prefix`、`XmlElement::namespace/prefix` 返回 `Option<String>`（冻结测试的 facts 投影 `map(Json::Str)` 需 owned；`DexText::as_str` 本就返回 `Option<String>`，同型）。`interfaces.md §1` 只冻结模型与语义，未冻结 getter 签名。
2. **渲染器丢开括号**：`render_element` 从未写出 `<`，所有元素开 tag 缺 `<`（facts 的 `xml` 逐字符比较立即暴露）。已补。
3. **qualified name 校验**：原实现把 `prefix:local` 整体喂给 XML `Name` 产生式（第 5 版已把 `:` 移出 Name），任何带前缀名字渲染必失败（`invalid XML name "android:minSdkVersion"`）。改为 prefix 与 local 各自按 Name 校验（每段 NCName，合起来恰一个冒号）——保留"非法名字是错误"的合同。
4. **混合内容缩进**：混合文本元素的内联子元素不再重排缩进（原实现给内联子元素 indent(depth+1)，违反 §1"混合文本不插缩进"）；拆出 `render_element_inline`（无前导缩进、深度限制语义不变）。
5. **to_xml 接缝语义**：声明行、prolog/epilog 的 Comment/PI、root 以单个 LF 接缝连接，文档无尾随 LF；whitespace Misc 项只钉文档位置、不产出文本（facts 的 prolog/epilog 数组保留它们，`xml` 字符串不含双换行——两条 facts 在原实现下互相矛盾，现同时成立）。
6. **纯 XML PI 内容**：quick-xml 的 `pi.content()` 保留 target 后的分隔空白（`" mode=gen"`）；按 XML 1.0 PI 产生式，target 之后的空白是分隔符不是内容，解析时剥离（facts: `mode=gen`）。
7. **元素间布局空白**：元素内部纯空白 text run 不再记录为 `XmlNode::Text`（facts 的节点数组不含它们；AXML 孪生从不携带此类节点，渲染器本就把 whitespace-only text 视为可忽略）；prolog/epilog 的空白仍按 Misc 保留（facts 需要它们钉位置）。含任何非空白字符的 text（含首尾空白）原样保留。
8. 杂项 lint/格式：`saturating_add`/`saturating_sub`、2^-31 字面量取最短往返表示（数值不变）、A07/A08 读面与 `decode()` 桥按 impl/function 级 `#[allow(dead_code)]` 标注（bin target 在接线前无调用方）、两处 `}fn`/`}    if` 排版修正。

## 5. facts vs 字节：两处不一致的裁决（附证据）

**A. 已提交输入字节错误（修字节，facts 不动）。** 会话开始时的已提交 `man01-last-manifest-entry.apk`/`man03-cdata-pi-node-order.apk` 把属性 `ns` 字段写成 **prefix 字符串索引**（man01 versionCode ns=2='android'；man03 app:tag ns=2='app'），而 AXML 格式（aapt `ResXMLTree_attribute`）里属性 `ns` 携带 **URI 字符串索引**，只有 namespace chunk 才是 (prefix, uri) 对。证据：(1) 解码报错 `cannot determine a prefix for namespace URI android/app`；(2) 同批 man02 全部属性用 URI 索引、 facts 解码正确；(3) 手编 facts 钉死 versionCode/tag 的 `ns` 必须是完整 URI。修复 builder 后重生成两个 APK（size 不变：1241/1002），`manifest.json` 对应两条 sha256 更新：
- man01-last-manifest-entry：`5ad04565…1dded` → `abb2b133…0528247`
- man03-cdata-pi-node-order：`d884eb4e…e5e93` → `45aed21d…2b5365b`

**B. man02 的 `xml` 事实缺渲染前缀（修 facts 格式，行为断言不动）。** 该文件 `nodes[0].attrs` 钉死首属性 `prefix:"xmlns"`、n01–n33 `prefix:"android"`（行为断言，未动），但同文件 `xml` 字符串写成 `android="http://…" n01="…"`——与自家 nodes facts 矛盾，且与 man01（`xmlns:android=…`、`android:versionCode=…`）、man03（`xmlns:app=…`）用同一渲染器的事实文件不一致；渲染器不可能对 man02 特殊化去掉前缀。裁决为手编笔误：仅把 `xml` 事实改为 `xmlns:android="…" android:n01="…"…android:n33="…"`，全部 typed 值/转义/节点/诊断/meta 零改动（python 脚本替换后逐值校验）。

## 7. 给 A07/A08 的接口说明

- 入口：`manifest::decode_manifest_entry(&[u8], &XmlDecodeLimits, &OperationControl) -> Result<Report<Manifest>, Error>`。分派：UTF-16 BOM → UnsupportedFormat；合法 UTF-8 且首个非空白为 `<`（剥 BOM）→ 纯 XML 路径；`0x0003` 文档 chunk 且声明 size ≤ 输入 → AXML；其余 MalformedInput。manifest 操作不要求 DEX entry 存在/有效（MAN-01 缺 manifest 的 NotFound 由 A07 的 read_entry→Engine 接线产生）。
- 序列化：`Manifest::to_xml(&XmlRenderOptions, &OperationControl) -> Result<String, Error>`。规范形：声明行、4 空格缩进、LF、接缝语义（§3.5）、混合内容内联不插缩进、非法字符/名字报 UnsupportedEncoding/MalformedInput、输出字节与深度有界。默认 limits = interfaces §5（depth 256、xml-nodes/attributes 1e6、string-units 1_048_576；输出 128 MiB/depth 256）。
- 取消：`OperationControl::new/with_cancel_flag/with_deadline`，`check()` 映射 Cancelled(User/Deadline)；解码与写出均设检查点。
- 模型读面（A08 facts 投影）：`Manifest::{declaration,prolog,root,epilog,metadata,raw_bytes}`、`XmlElement/XmlAttribute` 的 `namespace()/prefix()` 返回 `Option<String>`、`local_name()` 返回 `&str`、`ManifestValue::{as_text,raw_typed}`、`TypedValue::{type_byte,data,raw_string,format}`。`raw_bytes` 保留字段当前恒 `None`（纯 XML 原始字节例外留 A07/A08 接线）。
- 待删桥：`manifest::decode(&[u8]) -> anyhow::Result<String>`（`src/main.rs:163` 唯一调用点）；A07 改走 `decode_manifest_entry`+`to_xml` 后删除。`src/apk.rs` 本包未触碰、也无需兼容桥（其中无 manifest 调用点）。

## 8. 已知限制

1. 纯 XML 元素内部的纯空白 text（tag 间排版空白）不进文档模型（facts 如此钉定；AXML 孪生从不携带）；含非空白字符的 text 原样保留。若 A08 需要逐字节 round-trip 保真，走 `raw_bytes` 保留字段（§7）。
2. PI target 后的整段空白视为分隔符；`<?t  a?>` 与 `<?t a?>` 同内容（facts 只钉单空格形态）。
3. AXML 格式本身无 prolog/epilog 概念：注释/行号只存在于元素/CDATA 元数据，AXML 文档的 prolog/epilog 恒空。
4. `to_xml` 输出无尾随换行（接缝语义）；消费方（CLI）如需文件尾换行自行追加。
5. release-profile mutation smoke 与部分门禁在共享工作区的并行改动（A02 `src/zip.rs`/`src/dex/**`）短暂无法编译期间，曾在"HEAD 恢复这些文件 + 仅含本包变更"的快照副本上验证后于实时工作区复跑确认；contract_input/contract_references/bin dex 测试的失败归并行包。
