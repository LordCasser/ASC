## ADDED Requirements

### Requirement: 内存额度对应真实存活资源
Engine SHALL 在受计量资源分配前取得额度，在最后一个资源拥有者释放后归还。合同 MUST 明确覆盖和未覆盖的分配类别，不把操作结果大小或输入大小上限当作 RSS 保证。

#### Scenario: 返回值仍被消费者持有
- **WHEN** 第一份报告尚未释放且第二次操作申请共享预算
- **THEN** 第一份报告的受计量内存仍占用额度，第二次操作在剩余额度不足时明确失败

#### Scenario: 取消或后置坏 DEX
- **WHEN** 解析分配多个阶段后因取消或坏 DEX 失败
- **THEN** 所有已释放资源对应额度归还，下一操作可正常使用；仍存活的 artifact 占用不被错误清零

### Requirement: 中间结构不可绕过预算
扫描与解析 SHALL 在 hits、解压和工作结构分配前应用所声明的预算范围；无法精确度量的第三方工作集 MUST 公开实际限制。

#### Scenario: 小结果与巨大中间索引
- **WHEN** 最终仅一条命中但构建 hits/index 所需内存超过工作额度
- **THEN** 在越界分配前返回 ResourceLimit，不能因结果很小而绕过工作集边界
